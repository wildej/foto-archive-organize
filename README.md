# Фотоархив

Сводит две копии одной коллекции — папку на компьютере и выгрузку Google Photos — в одно дерево:

```text
год/месяц/альбом/снимок.jpg
год/месяц/альбом/_source/снимок.NEF
год/месяц/альбом/Видео/ролик.mp4
```

Месяц всегда `01`–`12`. Программа ничего не удаляет и не переписывает в исходных папках. Обычный запуск — сухой прогон: он только пишет план. Копирование начинается отдельной командой `apply`, и повторный `apply` не трогает уже совпавшие файлы.

В кластере, где есть и оригинал, и правка, остаётся правка. Отдельной очереди «посмотреть глазами» нет.

## Установка

Нужен Python 3.11+. В этом окружении нет `uv`, поэтому используется обычное виртуальное окружение.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
pip install -e .
```

## Windows

В PowerShell:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
pip install -e .
photoarchive plan --computer D:\Фото\Архив --google D:\Takeout --plan D:\Фото\plan.json
photoarchive apply --plan D:\Фото\plan.json --output D:\Фото\Архив-чистый
```

Если активация скрипта запрещена политикой, для текущего окна достаточно `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`, затем снова `.\.venv\Scripts\Activate.ps1`.

Проверка на синтетических файлах:

```bash
pytest
```

JPEG из RAW ищется в таком порядке: пакет `rawpy`, команда `darktable-cli`, команда `dcraw_emu` (LibRaw). Если ничего из этого нет, план всё равно строится. `apply` копирует RAW в `_source` и сообщает, что JPEG не собран. Свой конвертер можно передать флагом `--raw-converter`: к команде добавятся путь RAW и путь JPEG.

```bash
pip install rawpy
# или
sudo apt install darktable
```

Для HEIC дополнительно ставится `pillow-heif`. Без него HEIC копируется как есть, а в сводке будет предупреждение. Свой конвертер: `--heic-converter`.

## Сухой прогон

Достаточно одного корня, если второй копии под рукой нет.

```bash
photoarchive plan \
  --computer ~/фото-компьютер \
  --google ~/Takeout \
  --plan plan.json
```

Та же команда без слова `plan` (это режим по умолчанию):

```bash
photoarchive --computer ~/фото-компьютер --google ~/Takeout --plan plan.json
```

Повторный скан можно ускорить кэшем отпечатков:

```bash
photoarchive plan --computer ~/фото-компьютер --google ~/Takeout \
  --plan plan.json --index .photoarchive/index.sqlite
```

На экран выводится сводка:

- файлов просмотрено
- точных дублей схлопнуто
- групп ресайзов
- кластеров правок, где оставлена правка
- пар RAW+JPEG
- конвертаций RAW, у которых не было JPEG
- видео и WAV
- мусора
- конфликтов альбомов

Исходные файлы после этого не меняются, выходная папка не создаётся.

Посмотреть сводку ещё раз:

```bash
photoarchive summary --plan plan.json
```

## Копирование

```bash
photoarchive apply --plan plan.json --output ~/фотоархив
```

В выходной каталог попадают только выбранные копии. Если файл уже лежит на месте и его содержимое совпадает, он пропускается. Чужой файл с тем же именем не перезаписывается. Выходной каталог не может находиться внутри исходного.

Повторный `apply` безопасен: уже сделанная работа не выполняется заново.

## Как выбирается дата

Для папок `год/месяц` берётся первая найденная дата:

1. EXIF `DateTimeOriginal`. Если рядом есть `OffsetTimeOriginal`, день и месяц берутся из этих местных часов, а не из UTC.
2. Иначе `photoTakenTime` из JSON Google Takeout. Это момент в UTC. Он не считается местным временем компьютера и не сдвигается в пояс машины.
3. Иначе другие даты EXIF (`DateTimeDigitized`, `DateTime`).
4. Иначе дата из имени файла (`IMG_20181103_120000.jpg` и похожие).
5. Иначе время изменения файла.

Год и месяц из названий родительских папок сами по себе датой не считаются. Если у снимка нет EXIF, JSON и даты в имени, в план попадёт mtime — у скопированного архива это может быть время копирования, а не съёмки.

## Как выбирается альбом

1. Папка альбома Google Takeout, если файл лежит в альбоме, а не в служебной папке вроде `Photos from 2019`.
2. Иначе последняя папка старого архива, если это не год и не месяц (`2019`, `06`, `июнь`).
3. Иначе `Разное`.

Имена папок чистятся от символов, которые нельзя положить в путь. Если у одного кадра несколько разных имён, в путь берётся альбом Google, а спор записывается в план.

## Дубли

Сравнение идёт по всем снимкам сразу: дубли внутри компьютерного архива, дубли внутри Takeout и совпадения между этими деревьями схлопываются одинаково. Видео и WAV с фотографиями не склеиваются.

- Одинаковые байты или одинаковые пиксели схлопываются в один файл. Туда же попадает повторно сжатый JPEG того же размера, если средняя разница пикселей на уменьшенной копии не больше 12 (порог `MAD_SAME`): остаётся более тяжёлый файл.
- Чистый ресайз — pHash очень близкий, пропорции те же, число пикселей заметно меньше. Остаётся большее число пикселей, при равенстве — более тяжёлый файл.
- Правка — суффикс Google `-edited`, поле `edited: true` или title с `-edited` в JSON Takeout, кроп (другие пропорции при похожем pHash) или цветовой сосед (тот же размер, pHash близкий, пиксели уже заметно другие). В архив копируется правка, даже если она меньше оригинала. Остальные JPEG этого кадра не копируются.
- Если явной пометки нет, кропом считается кадр с другими пропорциями, а не полноразмерный оригинал. У цветовой пары без пометки берётся файл с более поздним временем изменения.
- RAW не выбрасывается как дубль JPEG. Пара остаётся парой.

Пороги лежат в `src/photoarchive/cluster.py`.

## RAW, sidecar, HEIC

RAW: NEF, NRW, ORF, DNG, CR2, CR3, ARW, RW2, RAF, PEF, SRW и ещё несколько камерных расширений из `classify.py`.

Если рядом есть JPEG (в том числе `-edited`), JPEG остаётся в папке альбома, RAW — в `_source`. Если JPEG нет, план ставит конвертацию: JPEG в альбом, RAW в `_source`.

Рядом с RAW в `_source` едут sidecar Capture One (`.cos`, `.cof`, `.cop`) и `.xmp` / `.pp3`, если имя совпадает со снимком или с полным именем RAW (`DSC_1000.NEF.xmp`).

HEIC хранится в папке альбома. Если конвертация доступна, рядом пишется JPEG. Если нет — остаётся HEIC и запись в предупреждениях.

## Видео и звук

MP4, MOV, AVI, m4v и 3gp переносятся в `{год}/{месяц}/{альбом}/Видео/`: файл уходит из исходной папки, вторая копия не создаётся. WAV копируется в ту же папку. Дата и альбом те же, что у фотографий. В папке альбома остаются снимки и каталог `_source`.

Повторный `apply` по старому плану тоже переносит видео. Если ролик уже был скопирован и содержимое совпадает, исходный файл удаляется. Точные копии роликов схлопываются между собой. С кадрами они не сравниваются. GIF считается изображением и остаётся среди снимков.

## Что пропускается

- JSON Google Takeout — это подпись к файлу, не медиа. Из него читаются `photoTakenTime` и признак правки.
- Мусор: `.lnk`, `.tmp`, `.doc`, `.zip`.
- Файл без понятного расширения — в сводку «неизвестных», в архив не копируется.

## Повторный запуск

План можно собрать заново: состав действий от входных файлов не зависит от времени записи плана. `apply` сверяет хеш. Совпавшую копию не пишет второй раз, исходник не открывает на запись.
